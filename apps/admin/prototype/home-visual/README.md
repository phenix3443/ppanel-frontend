# PROTOTYPE：管理后台 Home 视觉稿

> 一次性原型，不合入 main。Board 选定方向后，由 CTO 安排按本文的 token 和验收标准重新实现。

双击 `index.html` 打开。底部蓝色浮条不属于设计，只用来切换：

- `←` / `→`（或键盘方向键）：切换变体 A / B / C
- 正常 / 需关注 / 空数据：切换数据场景，检查状态色和空状态
- 主题：深色 / 浅色

URL 可直接分享，例如 `index.html?variant=B&scenario=alert&theme=dark`。`shots/` 里有 1440px 宽的截图。

## 用户与使用场景

用户是 ppanel 的管理员（目前就是站长本人）。打开 Home 时要回答三个问题：

1. 有没有东西坏了：服务器离线、工单积压
2. 今天生意怎么样：收入、注册、新购、续费
3. 流量去哪了：今日/本月总量，哪些节点、哪些用户用得最多

> 待验证假设：问题 1 的优先级高于问题 2。我们手上没有使用数据或访谈记录，这个排序是根据后台导航分组（运维排在商业前面）和工单/离线这类事项的时效性推出来的。Board 确认方向时请一并确认或推翻。

数据范围和现有页面完全一致，都来自 `getConsoleServer`、`getConsoleTicket`、`getConsoleRevenue`、`getConsoleUser` 和系统版本接口，没有新增字段，也没有新增操作。唯一的操作仍然是「系统重启」。

## 三个变体

| | A 沿用结构 | B 运维优先（推荐） | C 领域分栏 |
|---|---|---|---|
| 首屏第一眼 | 6 张等权 KPI 卡 | 运行状态条：离线服务器、待处理工单、版本 | 左「业务」右「运行」两栏 |
| 指标呈现 | 卡片网格 | 一条横向指标带，4 个数字用细分隔线分开 | 收入用 36px 大数字，运行指标用小卡 |
| 收入 / 用户图表 | 两张卡并排 | 合并进一张卡，用分段控件切换 | 各占一张卡，收入卡固定显示本月每日柱图 |
| 流量排行 | 节点、用户两张卡 | 右侧一列，节点/用户切换 | 右栏一张卡，节点/用户切换，前 8 名 |
| 实现成本 | 最低，只改样式 | 中等，要重排 `statistics.tsx` | 中等偏高，布局和卡片内容都要改 |

推荐 B，理由：

- 出问题时，状态条整条描边变黄，离线服务器变红色徽标，不用扫 6 张卡去找哪个数字异常。正常时状态条是一行灰色徽标，不抢视觉。
- 「今日收入」上提到指标带里，和在线用户、流量并列，回答问题 2 不用往下滚。
- 排行改成列表加细进度条，节点名和流量数值都能直接读，不再依赖 hover 提示。

A 适合想先低成本换肤、以后再调结构的情况。C 的大数字收入最有冲击力，但把服务器和工单放到右栏中段，出问题时不够显眼。

## Token

来源：从 https://u.bws.lol 的生产 CSS（`/assets/index-B4lHkPsn.css`）读取的 `--ds-*` 变量。我改了两处，原因写在表后。

### 颜色（深色，默认）

| Token | 值 | 用途 | 对比度（文字类，对 surface `#25221e`） |
|---|---|---|---|
| `canvas` | `#151412` | 页面底色 | |
| `foundation` | `#1e1c19` | 侧栏、顶栏 | |
| `surface` | `#25221e` | 卡片 | |
| `surface-raised` | `#2d2924` | 卡片内二级块、hover、选中分段 | |
| `border-subtle` | `rgba(236,226,214,.12)` | 卡片描边、分隔线 | |
| `border` | `rgba(236,226,214,.18)` | 控件描边 | |
| `border-strong` | `rgba(236,226,214,.32)` | hover 描边 | |
| `text-1` | `#f2ede5` | 标题、数字 | 13.6 : 1 |
| `text-2` | `#c8c0b7` | 标签、正文 | 8.8 : 1 |
| `text-3` | `#9e958b` | 辅助说明、坐标轴 | 5.4 : 1 |
| `signal` | `#e99432` | 品牌强调、当前导航、前三名、主数据系列 | 6.6 : 1 |
| `on-signal` | `#24170b` | 橙色底上的文字 | 7.3 : 1（对 signal） |
| `success` | `#67bd91` | 在线、无待处理 | 7.0 : 1 |
| `danger` | `#ee8178` | 离线、系统重启 | 6.1 : 1 |
| `warning` | `#e3c160` | 待处理工单、需关注 | 9.1 : 1 |
| `info` | `#79acd0` | 第二数据系列（续费） | 6.5 : 1 |
| `structure` | `#9e958b` | 第三数据系列（注册） | |

状态色都配一个 14% 透明度的 `*-soft` 底色，用于徽标背景。最低的一项是 `text-3` 放在 `surface-raised` 上，4.9 : 1，仍高于 WCAG AA 的 4.5。

和参考站不同的两处：

1. **warning 与 signal 分开。** 参考站里 `--ds-warning` 直接等于橙色 `--ds-signal`。后台里橙色已经是品牌色，会出现在当前导航、排行前三和图表主系列上，如果「待处理工单」也用橙色，管理员分不清哪个是装饰、哪个要处理。所以 warning 改为偏黄的 `#e3c160`。
2. **去掉毛玻璃和大投影。** 参考站卡片带 `backdrop-filter: blur(24px)` 和 `0 20px 52px` 的投影。后台一屏有十几张卡和图表，blur 影响滚动性能，大投影让层次变脏。这里只保留顶部 1px 内高光（`inset 0 1px 0 rgba(255,248,238,.05)`），层次靠三档底色加细描边。

### 浅色（保留切换）

现有后台支持主题切换，参考站也有浅色 token，所以一并给出。参考站浅色里 `text-3`、`danger`、`info` 在 `#f1f0ed` 上不到 4.5 : 1，我调深了；`success` 达标但为了和其他状态色的明度一致也略调深；`warning` 是新增的：

| Token | 参考站 | 本稿 | 对比度（对 canvas） |
|---|---|---|---|
| `text-3` | `#817b75`（3.7） | `#6b665f` | 5.0 |
| `danger` | `#b95049`（4.3） | `#a3443d` | 5.3 |
| `info` | `#4d748f`（4.4） | `#456a83` | 5.1 |
| `success` | `#34775a`（4.7，达标） | `#2f6d52` | 5.4 |
| `warning` | 参考站等于橙色 | `#785c00` | 5.5 |

其余浅色值见 `index.html` 的 `[data-theme="light"]`。

### 字体

- 正文：`IBM Plex Sans` + `Noto Sans SC`，与参考站一致
- 数字：同一字体，开启 `font-variant-numeric: tabular-nums`，数字刷新时宽度不跳
- 等宽：`IBM Plex Mono`，用于版本号、订阅 ID、排行里的流量值

字号阶梯：

| 用途 | 字号 / 字重 |
|---|---|
| 页面标题 | 22 / 600 |
| 卡片标题 | 15 / 600 |
| 正文、标签 | 13–14 / 400 |
| 辅助说明 | 12 / 400 |
| KPI 数字 | 28 / 600 |
| 重点数字（C 的收入） | 36 / 600 |
| 卡片底部汇总 | 18 / 600 |

原型从 Google Fonts 加载字体。正式实现建议用 `@fontsource` 自托管，具体由工程决定。

### 圆角、间距

| Token | 值 | 用途 |
|---|---|---|
| `r-object` | 16px | 卡片 |
| `r-control` | 10px | 按钮、分段控件、导航项 |
| `r-compact` | 6px | 列表行 hover、小徽标内 |
| 徽标 | 999px | 状态徽标 |
| `gutter` | 24px（窄屏 16px） | 页面内边距 |
| `gap` | 16px | 卡片间距 |
| `pad` | 20px | 卡片内边距 |

间距基于 4px。现有页面卡片间距混用 12px 和 16px，统一成 16px。

## 卡片与数据模块层次

1. **底色三档**：canvas → surface（卡片）→ surface-raised（卡片里的选中项、hover）。不靠投影区分层级。
2. **橙色只做两件事**：标出「你在哪」（当前导航、选中的数据系列、前三名）和品牌主色。不用来表示状态。
3. **状态色只出现在有状态的地方**：服务器在线/离线、工单有无积压、重启按钮。正常时尽量用灰色徽标，异常时才上色，避免一屏红绿。
4. **图表配色固定顺序**：橙（新购 / 主系列）→ 蓝（续费）→ 暖灰（注册）。网格线 8% 透明度，坐标文字用 `text-3`。
5. **空状态**：虚线框加「暂无数据 / 有数据后自动显示」，不留空白卡片。0 台服务器时状态显示「尚未接入服务器」，而不是「系统运行正常」。

## 范围

- 只改 `/dashboard` 首页的视觉和布局
- 侧栏和顶栏只继承新 token（底色、描边、当前项高亮），结构不动；其他后台页面不在本次范围
- 不新增接口、字段、操作或客户端
- 赞助区保留现有逻辑（有有效赞助商才显示），只换样式

## 验收标准（交工程实现时使用）

1. Home 在深色主题下使用上述 token，`canvas` / `surface` / `surface-raised` 三档底色与截图一致。
2. 文字与状态色在其所在底色上对比度不低于 4.5 : 1（深浅两套都要满足）。
3. warning 与品牌橙色是两个不同的 token，「待处理工单 > 0」时用 warning，不用 signal。
4. 服务器离线数 > 0 或待处理工单 > 0 时，异常项在首屏可见且有颜色提示；两者都为 0 时不出现红色或黄色。
5. 所有接口返回空时，各图表和排行显示空状态，不出现空白卡片或 NaN。
6. KPI 和排行数字使用等宽数字（tabular-nums）。
7. 浅色主题可切换，满足第 2 条。
8. token 的作用范围只在 admin 应用内。`packages/ui/src/styles/globals.css` 被 user 端共用，实现时不能直接改全局值影响用户端。
9. 不改变现有数据来源、跳转链接（在线用户、服务器 → `/dashboard/servers`，工单 → `/dashboard/ticket`）和系统重启流程。

## 未验证项

- 移动端：headless Chrome 有最小窗口宽度限制，窄屏截图不可信，所以没有附图。CSS 里有 ≤760px 的单列规则，需要在真机或 DevTools 里核实。
- 真实数据量：mock 用的是 36 台服务器、10 条排行。服务器上百台、节点名很长时的截断效果未验证。
- 使用优先级假设（见上文）没有数据支撑。
